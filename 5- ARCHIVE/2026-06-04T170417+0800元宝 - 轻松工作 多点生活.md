这个报错的原因很简单： **你在 CC-Switch 里配置的模型名称（Model Name）填的是 `DeepSeek-V3.2` ，但 DeepSeek 官方的 Anthropic 兼容接口不接受这个字符串，只认 `deepseek-v4-pro` 或 `deepseek-v4-flash` （全小写、无版本号）。**

## 🔍 原因说明

DeepSeek 新推出的 Anthropic 兼容 API（ `/anthropic` 路径）要求 model 参数必须是以下二者之一：

你在 CC-Switch 的模型映射/自定义模型名里填了 `DeepSeek-V3.2` （或旧版的 `deepseek-chat` / `deepSeek-V3` 之类），服务端校验不通过，直接返回 HTTP 400。

> 💡 补充说明： `DeepSeek-V3.2` 是底层模型版本代号， **不是 API 可调用的 model 参数值** 。V3.2 现在通过 `deepseek-chat` （即将废弃）或新版的 `deepseek-v4-flash` 路由，不能直接传版本号。

---

## ✅ 解决方法

在 CC-Switch 中修改 DeepSeek Provider 的配置：

| 配置项 | 正确填写值 |
| --- | --- |
| **Base URL** | `https://api.deepseek.com/anthropic` |
| **Model / 主模型** | `deepseek-v4-pro` （推荐）或 `deepseek-v4-flash` |
| **Sonnet / Opus / Haiku 映射** （如有） | 同上，都填 `deepseek-v4-pro` |
| **API Key** | 你的 `sk-` 开头 DeepSeek Key |

⚠️ 注意：

- •
	**必须全小写** ，不能有空格、 `[1m]` 后缀或版本号
- •
	Base URL 末尾 **不要带多余斜杠 `/`**
- •
	如果 CC-Switch 有"模型映射/Model Override"页，确保里面也没有残留的 `DeepSeek-V3.2`

改完保存后重新测试连接即可。
