# 知识库一致性检测 Skill

## 概述

扫描知识库的关键系统文件（模板、规范、CLAUDE.md、Skill），检测它们之间的交叉引用是否一致，输出差异报告。

**核心原则：模板是唯一事实来源。**

- 模板 YAML 字段 → 操作规范应如实记录
- 模板与 type 映射 → CLAUDE.md 应与操作规范一致
- Skill 不应硬编码模板信息（硬编码的应标记为风险项）

---

## 检测流程

### Step 1：收集基准数据

读取以下文件获取基准信息：

#### 1a. 所有模板文件

扫描 `9 - SYSTEM/Templates/` 下所有 `.md` 文件，对每个模板提取：

- 文件名（不含路径和扩展名）
- YAML frontmatter 中的所有字段名
- 正文中的节标题（`## ` 行）
- `type` 字段值

#### 1b. 操作规范 `9 - SYSTEM/知识库操作规范.md`

定位以下信息段：

- `type 值列表` — 所有已注册的 type
- `各类型专属字段` 段 — 每个 type 的专属字段
- `可用模板列表` — 所有模板条目
- `文件命名规则` 表

#### 1c. CLAUDE.md

定位以下信息段：

- `知识库速览` 结构图
- `type 与模板速查` 表
- AI 操作规则列表

#### 1d. 所有 Skill 文件

扫描 `.claude/skills/*/SKILL.md`，对每个 Skill 提取：

- 是否硬编码了模板路径（如 `9 - SYSTEM/Templates/xxx.md`）
- 是否硬编码了 YAML 字段名
- 是否硬编码了知识库文件夹路径（如 `3 - KNOWLEDGE/1-Reference/1-Books/`）

#### 1e. 变更记录 `9 - SYSTEM/变更记录.md`

- 读取最近 10 条变更记录
- 检查是否有标记为 `🔄 待同步` 的条目

---

### Step 2：逐项比对

#### 2a. 模板 → 操作规范检测

对每个模板文件，逐项检查：

| # | 检测项 | 规则 |
|---|--------|------|
| 2a.1 | type 存在性 | 模板的 `type` 是否在操作规范的 `type 值列表` 中 |
| 2a.2 | 专属字段完整性 | 模板的 YAML 字段（除 title/type/created/updated/tags 等通用字段外）是否与操作规范中对应 type 的"各类型专属字段"一致 |
| 2a.3 | 多余字段 | 模板中有但操作规范未记录的专有字段 |
| 2a.4 | 缺失字段 | 操作规范中有记录但模板中不存在的专有字段 |
| 2a.5 | 模板存在性 | 模板是否出现在操作规范的 `可用模板列表` 中 |

**排除通用字段**: `title`, `type`, `created`, `updated`, `tags`, `aliases` 视为通用 frontmatter 字段，不计入专有字段比对。

#### 2b. 操作规范 → CLAUDE.md 检测

| # | 检测项 | 规则 |
|---|--------|------|
| 2b.1 | type 映射 | 操作规范的 type 列表是否与 CLAUDE.md 的 `type 与模板速查` 表一致 |
| 2b.2 | 模板引用 | 每个模板名称在两边是否都能找到对应行 |
| 2b.3 | 字段信息 | CLAUDE.md 中的专属字段列是否与操作规范一致 |

#### 2c. Skill 硬编码检测

| # | 检测项 | 规则 |
|---|--------|------|
| 2c.1 | 模板路径 | Skill 是否引用了 `9 - SYSTEM/Templates/` 下的具体文件，该文件是否存在 |
| 2c.2 | 文件夹路径 | Skill 是否硬编码了输出路径（如 `3 - KNOWLEDGE/1-文献笔记/*`），该路径在当前结构中是否有效 |
| 2c.3 | YAML 字段 | Skill 是否直接操作特定 YAML 字段名，这些字段在当前模板中是否存在 |

**注意**: Skill 硬编码本身并不一定是问题，但需要标记让用户知晓。如果模板变更而 Skill 仍引用旧字段/路径，则标记为 ⚠️。

#### 2d. 变更记录检查

| # | 检测项 | 规则 |
|---|--------|------|
| 2d.1 | 待同步条目 | 变更记录中是否有 `🔄 待同步` 的条目，如果有，列出这些条目 |
| 2d.2 | 变更记录完整性 | 对比模板文件的修改时间与变更记录，如果模板最近被修改但变更记录无对应条目，提示用户 |

---

### Step 3：生成检测报告

将检测结果整理为结构化报告，按以下格式输出：

````markdown
# 📋 知识库一致性检测报告

**检测时间**：YYYY-MM-DD HH:mm

## ✅ 总体结果

> **N 项检查通过，M 项警告，K 项错误**

| 检查类别 | 通过 | 警告/错误 |
|---------|:---:|:---------:|
| 📄 模板 vs 操作规范 | ✅/⚠️/❌ | N 项 |
| 📖 操作规范 vs CLAUDE.md | ✅/⚠️/❌ | N 项 |
| 🤖 Skill 硬编码 | ✅/⚠️/❌ | N 项 |
| 📝 变更记录 | ✅/⚠️/❌ | N 项 |

## 📄 模板 vs 操作规范

### 一致的模板

| 模板文件 | type | 字段状态 | 节标题状态 |
|---------|:----:|:--------:|:---------:|
| 日记模板 | diary | ✅ 一致 | ✅ 一致 |

### 存在差异的模板

| 模板文件 | 差异类型 | 说明 |
|---------|---------|------|
| 日记模板 | ⚠️ 字段不一致 | 模板有 `location` 字段，操作规范未记录 |
| XX模板 | ❌ 缺失 | 操作规范中有记录，但模板文件不存在 |

**详细信息**（如有差异）：

**模板：日记模板（diary）**
- ⚠️ 多余字段：`location` → 操作规范未记录此字段
- ⚠️ 模板不在「可用模板列表」中（如果确实未列出）

## 📖 操作规范 vs CLAUDE.md

- ✅ type 映射：完全一致（N 个 type 全部匹配）
- ✅ 模板引用：N 个模板引用全部有效
- （如有差异则逐项列出）

## 🤖 Skill 硬编码检查

| Skill | 硬编码项 | 状态 |
|-------|---------|:----:|
| weread-book-note | `type: book`（符合模板） | ✅ |
| weread-book-note | `3 - KNOWLEDGE/1-文献笔记/1-读书笔记/` | ✅ 路径有效 |
| conversation-log | `3 - KNOWLEDGE/1-文献笔记/LLM问答/` | ✅ 路径有效 |

## 📝 变更记录

- ✅ 无待同步条目
- 或：
- 🔄 以下条目标记为「待同步」：
  - 2026-06-09：XXXX变更

## 💡 建议

- （如果有不一致）建议按优先级修复以下问题：...
- （如果是新增字段）建议更新操作规范的「各类型专属字段」段
- （如果是新增模板）建议同时在操作规范和 CLAUDE.md 添加对应条目
````

在报告中只列出**实际存在差异**的项。完全一致的部分用表格简洁汇总即可，不需要逐条展开。

---

## 注意事项

1. **只读不写**：本技能默认只做检测和报告，**不自动修改任何文件**，除非用户明确说"修复"或"同步"
2. **路径约定**：始终使用 vault 相对路径（不要以 `/` 或 `D:\` 开头）
3. **文件引用**：在报告中使用 `[[wikilink]]` 格式引用 vault 文件
4. **排除通用字段**：title/type/created/updated/tags/aliases 不计入专有字段比对
5. **Templater 语法**：模板中的 `<% tp.xxx %>` 语法是 Templater 动态替换，在检测时将其视为字段值的占位符，不作为差异
6. **图片使用**：可在报告中嵌入 `![[attachments/screenshot.png]]` 提升可读性
