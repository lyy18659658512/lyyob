# 对话日志整理

## Overview

将一段对话中信息密度最高的内容提取出来，按模板 `[[9 - SYSTEM/Templates/对话日志模板.md]]` 的格式整理为结构化笔记，存入 `[[3 - KNOWLEDGE/1-Literature/4-LLM/]]`。

核心产出是**独立可读的关键信息点**——让每条信息未来不需要重读整段对话就能被理解和引用。

## 输入来源路由

| 输入类型 | 预处理策略 |
|----------|-----------|
| 当前活跃对话 | 从对话历史中识别信息密集部分 |
| JSON 会话文件（`.claudian/sessions/`） | 读取 messages 数组，过滤 tool_use/tool_result 等技术消息 |
| INBOX 中的 AI 对话导出文件（如元宝、ChatGPT） | 直接解析正文，识别来源 AI 和原始文件名 |
| 已有 Markdown 对话日志 | 直接解析正文，保留已有结构做优化或补充 |
| 纯文本粘贴 | 启发式识别用户/LLM 角色边界 |

### INBOX 来源处理要点

INBOX 中可能存放来自外部 AI 的对话导出文件（如 `元宝 - 轻松工作 多点生活.md`）：
1. 从文件名或正文推断来源 AI 名称
2. **处理完成后将 INBOX 源文件移入 `5 - ARCHIVE/`**（保留原始记录备查，不删除）

## 核心原则

### 模板定义格式，技能填充内容

**文件结构、YAML 字段、信息点前缀、来源标注方式——所有关乎"怎么写"的规则，均由模板定义。**

- 写入前读取模板，严格按模板的 YAML 字段、节标题、示例格式进行填充
- 模板中的 Templater 语法（`<% tp.date.now() %>`、`<% tp.file.title %>`）替换为实际值
- 技能只负责判断"提取什么"和"放在哪个节"，不规定"写成什么样"
- 若模板更新，技能自动适配，无需修改

> ⚠️ **绝不自作主张**：YAML 字段中凡模板设为空值（`tags: []`、`links: []`、`aliases: []` 等），技能不得自行填入内容，**原样保留**留给用户填写。模板中的示例值（如示例标签）仅为展示格式，写入时也需清空。`model` 字段除外——当 `type: llm` 且能从文件名或正文推断出来源 AI 名称时，应自动填入。

### 输出路径与命名

| 项目 | 规则 |
|------|------|
| **输出路径** | `3 - KNOWLEDGE/1-Literature/4-LLM/` |
| **命名格式** | `{对话主题}.md`（见 CLAUDE.md：LLM 问答 → `对话主题.md`）——不含 AI 来源前缀，来源 AI 在正文段落中标注 |
| **日期** | `created` / `updated` 使用整理当天日期 |

## 处理流程

### Step 1 — 界定范围

#### 1a. 跨批次去重检查

先扫描 INBOX 待处理文件，快速比对 `3 - KNOWLEDGE/1-Literature/4-LLM/` 已有笔记：

1. `ls` 列出 `LLM/` 目录下所有文件名（仅一次 bash，几行输出）
2. 将 INBOX 文件名（排除时间戳前缀）与已有笔记标题做**模糊匹配**——主题关键词相同即视为重复嫌疑
3. 找到潜在重复后，只读已有笔记开头几行确认是否同一对话

**发现重复 → 在草案审核时提醒用户**，而非直接跳过。你来做最终判断是否重新整理或跳过。

#### 1b. 同批次去重检查

同一批次多个 INBOX 文件内容高度相似（相同 AI 来源 + 相同主题 + 相同角色序列）→ 同样在草案中标注，由你决定合并还是去重。

#### 1c. 话题分割判断

扫描待处理的对话，判断是否存在多个独立主题。**默认合并，除非有明显主题边界且各主题内容充分（各自至少 3-5 轮实质问答）。** 若有拆分必要，向用户提案。

### Step 2 — 话题分割与精选

按话题分段，每段保留信息密度最高的原始交流内容。

**精选原则**：
- ✅ 保留：信息密集的问答、概念解释、方法步骤、代码示例、对比分析
- ✅ 可精简：对 LLM 过长回答做适度精简，不改变原意
- ❌ 去除：问候语、重复确认、流程性对话、跑题内容

**话题划分**：
- 每个子话题独立成段，多轮递进追问合并到同一段
- 标题用简短的名词性短语（如"凯莱定理"而非"关于凯莱定理的讨论"），15 字以内
- 第三方 AI 对话（元宝、ChatGPT 等）在段落中标注来源 AI 名称

将精选内容按模板的格式填入 `## 精选对话记录` 节。

### Step 3 — 提取关键信息点

这是对话日志最核心的产出。从对话中提取**独立可读**的可复用信息。

**质量标准（每条必须同时满足）**：
1. **独立可读**——不看对话上下文也能理解
2. **信息完整**——包含定义、条件和上下文约束
3. **有来源标注**——每条指向其在对话中的出处
4. **结论而非过程**——提取的是知识本身，而非"讨论了什么"

**坏→好对比**：

| 不可独立读 | 独立可读 |
|-----------|---------|
| "对话中讨论了矩阵秩的定义" | "矩阵的秩 = 列秩 = 行秩，等于行阶梯形中非零行数" |
| "提到了对称差运算" | "对称差 Δ 运算：A Δ B = (A−B) ∪ (B−A)，单位元为空集 ∅，自身为逆元" |

按模板中的示例格式（前缀、来源标注等）写入 `## 关键信息点` 节。

### Step 4 — 草案审核

以草案形式展示整理结果，**不写入文件系统**。提交时让用户核验：
1. 话题分割是否合理？
2. 精选对话是否抓住核心？
3. 关键信息点是否准确且独立可读？

### Step 5 — 写入文件

用户确认后写入：
1. 读取模板 `[[9 - SYSTEM/Templates/对话日志模板.md]]`
2. 用精选内容和关键信息点填充对应节
3. 替换 Templater 语法为实际值
4. 写入 `3 - KNOWLEDGE/1-Literature/4-LLM/{对话主题}.md`

### Step 6 — 写入后自检

确认：
1. ✅ 文件路径正确
2. ✅ 所有关键信息点有来源标注
3. ✅ 没有残留 Templater 占位符（`<% ... %>`）
4. ✅ `## 对话背景` 描述了起因和范围
5. ✅ 精选已去除问候语和跑题
6. ✅ `created` / `updated` 已填充实际日期
7. ✅ 模板中空值字段（`tags: []`、`aliases: []` 等）未被技能填充，原样保留；`model` 除外——已按来源 AI 推断填入

### Step 7 — 归档源文件

自检通过后，将本次处理的 INBOX 源文件移入 `5 - ARCHIVE/`：

- **INBOX 来源** → 移入 `5 - ARCHIVE/`，保留原始文件名不变
- **JSON 对话文件（`.claudian/sessions/`）** → 不移入 ARCHIVE，保留在原位置（属于系统会话记录，非用户笔记）
- **已有 Markdown 对话日志的再整理** → 源文件不在 INBOX，无需归档

> 归档而非删除，保留原始记录备查，与 weread-book-note 的处理方式不同。

## 特殊场景

| 场景 | 处理 |
|------|------|
| 对话太短（<3 轮） | 仍可保存，提示用户建议与相关主题合并 |
| 代码密集 | 关键信息点以代码类内容为主 |
| 多不相关主题 | 必须提案拆分；用户坚持合并时标题用分隔符连接 |
| INBOX 文件含多条独立对话 | 按每条对话分别处理、分别写入 |
| JSON 结构异常 | 提示用户，回退到手动粘贴模式 |
| 文件名冲突 | 自动追加版本号 |
| **跨 INBOX 文件内容重复** | Step 1a 检测到已整理的重复内容 → 草案中标注，由用户决定跳过或重新整理 |
| **同批次 INBOX 文件内容重复** | Step 1b 检测到待处理文件之间内容相似 → 草案中标注，由用户决定去重或分别处理 |

## 错误处理

| 问题 | 处理 |
|------|------|
| 用户不满意 | 根据反馈调整草案，重新提交审核 |
| 来源标注遗漏 | 自检发现后立即补充 |
| 模板读取失败 | 检查 `9 - SYSTEM/Templates/对话日志模板.md` 是否存在；不存在时提示用户 |
