# 自定义技能触发控制配置

> **对话背景**：用户希望将知识库中的自定义技能（对话日志整理、对话总结）设置为仅在其显式指定时触发，而非根据关键词自动匹配调用。

---

## 精选对话记录

### 1. 问题的提出

**用户**：
只想自定义技能显示指定触发，需要如何设置。

**LLM**：
分析技能触发机制——技能触发由 SKILL.md 中 YAML 前言的 `description` 字段控制。系统根据用户输入与描述的匹配度决定是否触发技能。读取了 `对话日志整理` 和 `对话总结` 两个技能的 SKILL.md 配置文件，了解现有触发条件。

### 2. 方案探索与发现

**LLM**：
通过 `update-config` 技能查阅 `settings.json` 完整配置方案，发现关键字段 **`skillOverrides`**，其中 `"user-invocable-only"` 模式可以将技能从模型视野中隐藏但保留 `/名称` 调用能力，完美满足"仅显式触发"的需求。

### 3. 实施配置

**LLM**：
在项目 `.claude/settings.json` 中写入配置：

```json
{
  "skillOverrides": {
    "对话日志整理": "user-invocable-only",
    "对话总结": "user-invocable-only"
  }
}
```

**LLM**：
补充了 `skillOverrides` 四种模式：`on`（默认正常）、`name-only`（只显示名称无描述）、`user-invocable-only`（模型不可见但保留 `/名称` 调用）、`off`（完全隐藏）。还介绍了备选方案：在 SKILL.md 的 `description` 中加强约束语句，但不如 skillOverrides 彻底。

---

## 关键信息点

- **概念 / `skillOverrides` 设置项**：`settings.json` 中的 `skillOverrides` 字段可按技能名称控制其可见性和触发行为。模式包括：`on`（正常）、`name-only`（仅显名称）、`user-invocable-only`（隐藏描述，保留 `/名称` 调用）、`off`（完全隐藏）。
  来源：对话记录 §2

- **方法 / 配置自定义技能仅手动触发**：在 `.claude/settings.json`（项目级）或 `~/.claude/settings.json`（全局级）中添加 `"skillOverrides": { "技能名称": "user-invocable-only" }`，即可让该技能不自动触发，仅在用户输入 `/技能名称` 时响应。
  来源：对话记录 §3

- **方法 / SKILL.md 的 description 控制**：在 SKILL.md 的 YAML 前言的 `description` 字段中加强约束语句（如"⚠️ 仅当用户明确说出技能名称时触发"），可从描述层面降低自动匹配概率，但不如 skillOverrides 彻底。
  来源：对话记录 §3

- **方法 / skillOverrides 四种模式对比**：`on`（默认正常）→ `name-only`（只显示名称无描述）→ `user-invocable-only`（模型不可见，可 `/调用`）→ `off`（完全隐藏，不可用），逐级加强控制力度。
  来源：对话记录 §3
