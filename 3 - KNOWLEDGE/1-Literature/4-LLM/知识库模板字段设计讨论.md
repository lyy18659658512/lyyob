# 知识库模板字段设计讨论

## 对话背景

围绕学习吴恩达 Agent 智能体课程的实操需求，系统讨论了 Obsidian 知识库中多个笔记模板（course、project、article、atomic）的字段设计，涉及 url、progress、links、aliases、deadline、tags 等字段的取舍和定位，最终同步更新了模板、操作规范和 CLAUDE.md。

## 精选对话记录

### 1. 课程模板的 url 与 progress 字段

**用户**：课程笔记模板YAML是不是要加URL字段和标记是否完成的字段，还是说标记是否完成字段加在项目笔记里就好？

**LLM**：url 建议加课程模板（同文章模板的 url，指向源地址）。完成状态建议放项目笔记——项目笔记管生命周期（完了归档），课程笔记管知识沉淀（永不归档）。最终选了折中方案：加 `url` + `progress`（仿读书笔记，仅标记进度），完成状态仍在项目笔记管。

### 2. links 字段统一引入

**用户**：我想都加上一个links字段，通过字段来建立双向链接，你觉得怎么样

**LLM**：赞成加 links。YAML links 给 Dataview 和图谱看显式关系，正文 wikilink 给读者看上下文引用，两者不冲突。book 模板已有此字段先例。最终 project 和 course 模板都新增了 `links: []`。

### 3. deadline 字段的去留

**用户**：那不是和 status 字段重复了吗

**LLM**：deadline 只在 `status: active` + 有明确截止日期 这个组合下才真正有用，其余组合（ongoing/someday）都是空的，确实和 status 功能重叠。最终去掉 deadline，用 status 一个字段搞定。

### 4. aliases 字段差异化引入

**用户**：（逐轮）课程笔记需要别名字段吗？→ 文章笔记模板添加一下别名字段 → 原子笔记好像没有别名,是否需要呢？

**LLM**：aliases 的价值因笔记类型而异——course 和 article 的别名方便搜索引用，atomic 的别名收益最大（概念多名称，作为知识库枢纽节点被频繁引用，打错名字链路就断了）。project 名称唯一不加，diary 按日期导航不加，fleeting 临时笔记不加。最终 course、article、atomic 三个模板新增 aliases。

### 5. 标签策略讨论

**用户**：保留的好处是不是可以通过标签,聚合项目笔记吗？→ 那日记里也要标签吗？→ 闪念笔记呢？

**LLM**：tags 是所有模板通用字段，保留但不强制填写。项目按主题填（跨 type 聚合 AI 相关内容），日记仅标记里程碑日子（90%天数留空），闪念作为临时容器不需要标签（活不过一周，打标签没意义）。

## 关键信息点

- **概念 /** **字段定位**：`links` 用于管理笔记间的显式关联关系（给 Dataview 和图谱查询用），正文 `[[wikilink]]` 用于阅读时的上下文跳转，两者共存不冲突
  来源：对话记录 §2

- **概念 /** **职责分离**：project 管生命周期（完成→归档），course/book 管知识沉淀（永不归档），因此完成状态放 project、进度标记 progress 放 course
  来源：对话记录 §1

- **方法 /** **别名策略**：aliases 按笔记类型差异化引入——course/article/book/llm 便于搜索引用，atomic 收益最大（枢纽节点多名称），project/diary/fleeting 不加
  来源：对话记录 §4

- **方法 /** **标签使用策略**：tags 按需填写，不填为常态。项目按主题填以实现跨 type 聚合，日记仅标记里程碑/重要决定/生病等特殊日子（～10%），闪念笔记零标签（临时性，活不过一周）
  来源：对话记录 §5

- **事实 /** **deadline 冗余**：项目模板中 deadline 只在 `status: active + 有硬截止日期` 时有用，与 status 字段功能重叠，最终被移除简化
  来源：对话记录 §3

- **事实 /** **本轮模板改动**：course 模板 +url/progress/links/aliases；project 模板 +links/-deadline；article 模板 +aliases；atomic 模板 +aliases。同步更新了知识库操作规范和 CLAUDE.md
  来源：对话记录 §1-4
