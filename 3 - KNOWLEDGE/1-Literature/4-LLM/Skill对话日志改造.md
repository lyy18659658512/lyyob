# Skill对话日志改造

## 对话背景

将 `对话日志整理` skill 从旧仓库规范完全适配到当前 vault 的工作流，重新定义了 skill 与模板的角色边界——模板定义格式，技能只填充内容。同时清理了遗留配置（改名、移除工具限制）。

## 精选对话记录

### 1. Skill 路径与命名适配

**用户**：改造一下对话日志整理这个 skill，是从其他仓库拷贝过来的，不适用当前知识库的工作流

**LLM**：分析了差异后做了改造——
- 输出路径：`原始资料/对话日志/` → `3 - KNOWLEDGE/1-Reference/4-LLM/`
- 模板路径：`_templates/` → `9 - SYSTEM/Templates/`
- 文件命名：`{12位日期}_{主题}.md` → `{主题}.md`
- 新增 INBOX 输入源（元宝等外部 AI 对话）
- INBOX 源文件不删除（区别于 weread-book-note）

**用户**：tags 字段由用户自己填写，不需要延伸提炼原子笔记

**LLM**：移除了 tags 推荐和"可选延伸：提炼原子笔记"章节

### 2. 角色边界重定义

**用户**：格式约定是否有约定要遵循模板格式？如果我改了模板格式，skill 会有哪些影响？

**LLM**：分析了现状——skill 实际硬编码了多项格式（`### N. 标题`、`**概念 /**` 前缀、`来源：对话记录 §N`），与"以模板为准"的声明不一致。列举了改模板后各场景的影响。

**用户**：我希望技能只是对内容进行填充，由模板定义格式

**LLM**：重新设计了"模板定义格式，技能填充内容"的分界线，移除了所有硬编码格式规则

### 3. 清理遗留配置

**用户**：将技能名称改成英文

**LLM**：目录名和 frontmatter 统一改为 `conversation-log`

**用户**：allowedTools 是否是必须的？没有有什么影响？

**LLM**：检查了所有 8 个 skill，只有 `conversation-log` 有该字段。定位是可选限制，非必须

**用户**：评估删掉和不删掉利弊

**LLM**：分析了权限边界后建议删掉

**用户**：删掉

## 关键信息点

- **概念 / Skill 设计的核心原则**：模板定义格式，技能只填充内容。YAML 字段、节标题、信息点前缀、来源标注方式等所有"怎么写"的规则由模板定义，技能只负责"提取什么"。模板更新时技能自动适配，无需修改。
  来源：对话记录 §2

- **事实 / allowedTools 字段是可选限制**：在 Obsidian vault 的 skill 系统中，`allowedTools` 是限制性白名单，非必需。无此字段时技能继承 agent 的全部可用工具。其他 7 个 skill 均无此字段。
  来源：对话记录 §3

- **方法 / Skill 目录名与 frontmatter name 需一致**：skill 通过目录名注册到系统可用列表，frontmatter 的 `name` 应与之保持同名。
  来源：对话记录 §3
