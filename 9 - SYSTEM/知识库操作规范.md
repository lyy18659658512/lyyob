# 知识库操作规范

## 📁 文件夹结构

```
0 - INBOX           ← 外部收集（剪藏/WeRead/对话导出），每周清理
0 - FLEETING        ← 闪念笔记
1 - JOURNAL         ← 时间线
  └── 日记每天一篇
2 - ACTION          ← 行动
  ├── career/        ← 职业发展
  ├── business/      ← 创业
  ├── teaching/      ← 教学筹备
  ├── finance/       ← 财务
  ├── health/        ← 健康
  └── someday.md     ← 孵化池
3 - KNOWLEDGE       ← 知识沉淀
  ├── 1-Literature    ← 外部来源笔记
  │   ├── 1-Books
  │   ├── 2-Courses
  │   ├── 3-Articles
  │   └── 4-LLM
  └── 2-Atomic       ← 提炼的概念卡片
4 - CREATION        ← 预留（创作输出）
5- ARCHIVE          ← 已完成/过期的内容
6 - ATTACHMENTS     ← 图片/素材附件
7 - RESOURCE        ← 资源文件
9 - SYSTEM          ← 配置
  ├── Templates
  └── 知识库操作规范.md
```

## 📋 YAML Frontmatter 规范

所有笔记通用字段：
```yaml
---
title: ""
type: ""       # 见下方 type 列表
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: []
---
```

### type 值列表
- `fleeting` - 闪念笔记
- `diary` - 日记
- `project` - 项目
- `book` - 读书笔记
- `article` - 文章笔记
- `llm` - LLM 问答笔记
- `course` - 课程笔记
- `atomic` - 原子笔记
- `dashboard` - 仪表盘/首页
- `system` - 系统文档

### 各类型专属字段

```yaml
# book
author: "作者名"
cover: "6 - ATTACHMENTS/cover_书名.jpg"   # 封面图片本地路径，WeRead 导入时自动下载
progress: "30%"    # 阅读进度，如 "30%" 或 "120/300页"
links: []         # 关联笔记链接，如 ["[[写作不是从零开始]]"]
aliases: []       # 笔记别名，便于搜索

# article
author: "作者/来源"
url: "原文链接"
aliases: []       # 笔记别名，便于搜索

# course
platform: "课程平台"
instructor: "讲师名"
url: "课程链接"
progress: "学习进度，如 '3/8课' 或 '60%'"
links: []         # 关联笔记链接，如 ["[[学习计划]]"]
aliases: []       # 笔记别名，如 ["Agent课程", "吴恩达Agent课"]

# diary
mood:      # 可选
weather:   # 可选

# project
status: active | ongoing | someday  # 项目状态
links: []         # 关联笔记链接，如 ["[[相关课程笔记]]"]

# atomic
source: "[[来源文献笔记]]"
aliases: []       # 笔记别名，便于搜索

# llm
source: ""       # AI 来源名称
aliases: []      # 笔记别名，便于搜索

# fleeting, dashboard, system → 无专属字段
```

## 🔄 日常使用流程

### 随时
- 有想法 → 写入 0 - FLEETING（用闪念笔记模板），或直接写入对应文件夹
- 读书/上课/问AI → 直接写入 3 - KNOWLEDGE

### 每周（可选）
- 清理 INBOX，分发到对应文件夹
- 从文献笔记提炼原子笔记，建立链接

### 项目结束时
- 相关项目笔记移入 5- ARCHIVE

## 📄 使用模板创建笔记

模板存储在 `9 - SYSTEM/Templates/`，通过以下方式使用：

- **Obsidian 核心模板插件**：`Ctrl/Cmd+P` → `Templates: Insert template` → 选择模板

- 模板文件会自动填充 frontmatter 和日期，创建后手动补充正文

## 📖 微信读书笔记工作流

使用 `weread-book-note` skill 自动处理。

**触发方式**：对 Claude 说"整理读书笔记"、"更新读书笔记"、"处理微信读书笔记"等。

### 输出
- 路径：`3 - KNOWLEDGE/1-Literature/1-Books/{书名}.md`
- 模板：[[9 - SYSTEM/Templates/读书笔记模板]]

### 字段归属规则

| 来源 | 字段 | 说明 |
|------|------|------|
| **WeRead 自动抓取** | `title` `author` `progress` | 每次新建/更新都从源文件同步 |
| **系统自动生成** | `type` → 固定 `book` | 新建时设定 |
| | `created` → 首次创建日期 | 后续更新永不修改 |
| | `updated` → 处理当天日期 | 有新增内容时刷新 |
| **手动维护** | `tags` `links` | 更新时原样保留，**永不覆盖** |
| **正文占位符** | `摘要` `## 💡 关键收获` | 需手动补充，不会被自动填充 |

### 源文件处理

- INBOX 源文件在处理成功后**自动删除**，不保留备份
- 增量更新仅追加新 refID，已有摘录不受影响
- 若 WeRead 导出的 `progress` 变更，笔记中的进度会同步更新

## 💬 AI 对话日志工作流

使用 `conversation-log` skill 自动处理。

**触发方式**：对 Claude 说"保存这段对话"、"把对话整理成笔记"、"把聊天记录结构化"等。

### 输出
- 路径：`3 - KNOWLEDGE/1-Literature/4-LLM/{对话主题}.md`
- 模板：[[9 - SYSTEM/Templates/对话日志模板]]

### 字段归属规则

| 来源 | 字段 | 说明 |
|------|------|------|
| **技能自动填充** | `type` → 固定 `llm` | 新建时设定 |
| | `source` → AI 名称 | 从对话来源推断 |
| | `created` → 首次创建日期 | 后续更新永不修改 |
| | `updated` → 处理当天日期 | 有新增内容时刷新 |
| **手动维护** | `tags` `aliases` | 更新时原样保留，**永不覆盖** |
| **正文占位符** | `## 对话背景` `## 精选对话记录` `## 关键信息点` | 需手动审核后确认 |

### 源文件处理

- INBOX 中的第三方 AI 对话导出（如元宝、ChatGPT）→ 处理后**移入 5- ARCHIVE**（保留原始记录备查，不删除）
- JSON 会话文件（`.claudian/sessions/`）→ 保留在原位置，不移入 ARCHIVE

## 💡 原则

- 文件夹管类型，标签管主题
- INBOX 不是必经之路，而是兜底方案
- 知识类笔记永不归档，时效性内容才移入 ARCHIVE
- 无需背负回顾压力，顺其自然

## 🤖 一致性检测

进行系统级变更后，可让 AI 自动执行一致性检测：

### 检测命令

> **"帮我做知识库一致性检测"**
> **"检查模板和文档是否同步"**
> **"运行一致性检测"**
> **"知识库体检"**
>
> > 💡 以上命令会触发专门的 `consistency-check` Skill 执行完整检测

### AI 会检测的内容

1. **模板 vs 操作规范**
   - `9 - SYSTEM/Templates/` 下每个模板的 YAML 字段 → 与操作规范中 `各类型专属字段` 逐行比对
   - 是否存在模板有但规范未记录的字段
   - 是否存在规范有但模板未包含的字段
   - 模板列表是否与 `可用模板列表` 一致

2. **模板 vs CLAUDE.md**
   - type 与模板的映射关系是否一致
   - 模板是否在 CLAUDE.md 中有对应的 entry

3. **Skill vs 模板**
   - Skill 中硬编码的模板路径是否有效
   - Skill 硬编码的 YAML 字段是否与模板一致

4. **变更记录完整性**
   - 最近的系统变更是否已在 [[9 - SYSTEM/变更记录]] 中记录

### 检测结果处理

- AI 会生成差异报告，标记每项为 `✅ 一致` / `⚠️ 不一致`
- 如有不一致，可指示 AI 直接修复，或手动修复后重新检测
